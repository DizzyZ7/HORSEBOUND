## Why this release exists

0.5.0 establishes the persistent data and simulation contract required by the playable Homestead loop. It deliberately lands before the large rendering/input integration so that structures, storage, horse needs and hotbar state do not need another incompatible migration during 0.5.1.

## Inventory and resources

- per-stack limits are visual stack limits, not total inventory caps;
- totals above 99 wood or 20 apples survive load/save without truncation;
- stack views split aggregate counts for the upcoming inventory UI;
- added Stone, Carrot, Hay and Water Bucket;
- fresh ranches receive a small starter supply of hay and water;
- duplicate saved entries are summed and unknown future item IDs are ignored safely.

## Hotbar

- eight persistent slots;
- selected slot persists;
- empty and unknown slots restore safely;
- default order prepares Wood, Hay, Water, Apple, Carrot and Stone;
- the domain is ready for keyboard number keys, mouse wheel and controller shoulder/D-pad integration in 0.5.1.

## Homestead structures

Typed structure definitions now exist for:

- Fence;
- Gate;
- Feeder;
- Water Trough;
- Hay Storage;
- Chest;
- Stable Stall.

Each structure has:

- persistent UUID;
- type and transform;
- build cost;
- optional resource capacity;
- stored resource units;
- safe save/load conversion.

Placement checks every material before consuming anything. Failed builds leave inventory unchanged. Removing a structure can return a partial material refund.

## Horse care

Every horse now has persistent:

- hunger;
- thirst;
- energy.

The pure-Java care system supports:

- passive and activity-driven need drain;
- stronger drain during gallop;
- autonomous hay consumption from nearby feeders/storage;
- autonomous water consumption from nearby troughs;
- energy recovery near a stable stall while resting;
- explicit care events for future animation, audio and HUD feedback.

The model is intentionally forgiving: ranch infrastructure reduces repetitive chores instead of turning HORSEBOUND into a punishing survival game.

## Save format v4

Save v4 appends:

- horse hunger, thirst and energy;
- typed placed structures and stored units;
- hotbar slots and selection.

Migration behavior:

- v1–v3 files remain readable;
- legacy fences receive deterministic UUIDs and become typed Fence structures;
- old horses receive healthy need defaults;
- old worlds receive the default hotbar;
- a real binary v3 fixture is migrated, rewritten as v4 and loaded again in tests;
- backup recovery, temporary writes, disk flush and atomic replacement remain active.

## Scope boundary

The current packaged game remains visually compatible with 0.4.8. The new Homestead domain is packaged and validated but not yet fully exposed through the live ranch renderer.

0.5.1 will connect:

- visible hotbar selection;
- structure placement preview and snapping;
- feeders, troughs, gates and stalls in the world;
- resource deposits;
- horse need updates and visible feedback;
- v4 snapshot capture from the active ranch screen.

No Steam store feature will claim playable Homestead systems until that integration passes packaged controller and save/restart smoke tests.
