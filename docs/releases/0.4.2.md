# HORSEBOUND 0.4.2 — Simulation & Input Foundation

Created by **Dimash Janibekov (DizZyZ7)**.

## Purpose

This release starts decoupling gameplay simulation from rendering FPS and physical device APIs before horse needs, weather, crafting, larger herds and Steam Deck controls are added.

## Fixed-step simulation

- pure Java `FixedStepClock`;
- 60 deterministic simulation ticks per second;
- capped long-frame input;
- bounded catch-up work to prevent a spiral of death;
- interpolation alpha for future render interpolation;
- world time now advances through fixed simulation ticks;
- tests compare 30, 60 and 144 render FPS.

## Device-neutral input

- `PlayerCommand` models gameplay intent rather than key codes;
- `InputSnapshot` includes command data and the active prompt device;
- keyboard/mouse, gamepad and Steam Input device identities;
- current keyboard/mouse adapter;
- mixed-input command merging;
- command buffer between render sampling and fixed simulation;
- continuous movement persists;
- jump, interact, mount, build, save and pause edges are consumed exactly once.

## Next integration

Player, horse, Pushik and interaction systems will move behind this simulation/command boundary. The gameplay domain must stop reading `Gdx.input` directly before Homestead mechanics expand.
