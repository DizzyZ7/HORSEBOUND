## Release purpose

0.5.6 is a focused stabilization release for the first serious manual playtest of the current ranch loop. It deliberately does not introduce chunk streaming, weather, new save DTOs or other Living World systems.

## Confirmed input defects fixed

### Screen-transition controller edges

A newly created menu mapper previously compared the first controller frame with a disconnected frame. Holding Confirm, Back, Start or a D-pad direction while changing screens could therefore be interpreted as a fresh press on the next screen.

0.5.6 requires a neutral controller state before menu actions become active. Keyboard and pointer input remain immediately available.

### Gameplay-entry controller edges

The gameplay mapper now primes one-shot controller buttons on its first connected frame and after reconnect. Held buttons cannot cause an immediate jump, interaction, mount, build, inventory open, manual save or pause when gameplay begins.

Analog movement and camera input are not blocked. Toggle Sprint requires release and a fresh R1 press.

## Confirmed world-placement defects fixed

### Safe dismount

Dismount no longer assumes that the point beside the horse is dry and valid. A deterministic radial search chooses bounded non-lake ground, falling back to a known safe origin only when no local candidate exists.

### Safe Pushik recovery

The same safe-ground policy is used when Pushik catches up after falling too far behind and when invalid saved coordinates require a fallback during load.

### Homestead placement exclusions

Placement and relocation validation now rejects overlap with:

- live unharvested trees;
- procedural rocks;
- mounted or free horses;
- existing Homestead structures;
- lake, steep terrain and world boundaries as before.

## Confirmed HUD defects fixed

- the old hardcoded `HORSEBOUND 0.4.3` label is removed;
- the live HUD uses the packaged build version;
- keyboard prompts use the current device-local bindings rather than obsolete hardcoded keys;
- horse-care status is limited to a nearby horse rather than selecting one from anywhere in the world.

## Confirmed save-slot defects fixed

### Continuous overwrite confirmation

Overwrite confirmation is now tied to the continuously selected occupied slot. Moving selection away cancels it, so returning later always requires a new two-step confirmation.

### Ranch replacement recovery ownership

Creating a new ranch over an occupied slot now replaces both `save.hbs` and `save.bak` with the new ranch. If the new primary is damaged before the next autosave, recovery cannot resurrect the deliberately overwritten old world.

Ordinary saves still retain the previous valid primary as backup. Save format remains **v5** and existing migration/recovery behavior is preserved.

## Validation

The release gate covers:

- all existing save v1–v5 migration and recovery tests;
- ranch replacement backup regression;
- continuous overwrite-selection confirmation;
- controller transition and reconnect edge priming;
- Toggle Sprint after gameplay entry;
- safe-ground search around lake and world boundaries;
- nature and horse placement exclusion;
- current HUD copy and remapped key labels;
- Java 21 compilation and Windows `jpackage`;
- required 0.5.6 runtime classes inside the packaged JAR;
- exact version/commit identity and SHA-256 manifest;
- absence of saves, settings, logs and local Steam configuration from the app image.

## Honest test boundary

CI cannot evaluate actual gameplay feel, rendered readability, physical controller families, transparency/GPU behavior, audio balance or the complete player learning experience. Those are the primary goals of the 0.5.6 manual playtest.
