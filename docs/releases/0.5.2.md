## Inventory and chest storage

- the Inventory action is keyboard-rebindable and stored in device-local `input.properties`;
- controller D-pad Up opens the backpack outside placement mode;
- the active ranch remains alive while the overlay is open;
- the player backpack shows its 24-stack capacity;
- Chest provides 12 persistent item-stack slots;
- Left/Right changes the active panel;
- Confirm transfers one item per press;
- transfers are atomic and never delete an item when either side is full;
- old profiles without an Inventory binding receive the safe default without losing existing bindings.

## Save format v5

Save v5 persists operational structure state:

- Gate open/closed state;
- Chest item contents;
- moved structure transforms;
- existing feeder/trough storage;
- all previous v4 Homestead, hotbar and horse-care data.

Versions 1–4 remain readable. Real binary v4 migration coverage verifies that old Gates load closed and old Chests load empty before being rewritten as v5.

## Gates and structure physics

- Interact opens or closes a nearby Gate;
- the visible Gate rotates immediately;
- open Gates stop blocking movement;
- closed Gates, fences and other structures block the player, mounted horse and autonomous horses;
- swept-circle collision subdivides large movement steps so frame stalls cannot tunnel through a structure;
- collision radii are owned by structure definitions rather than duplicated inside the screen.

## Building edit mode

- `M` or controller D-pad Down selects the nearest editable Homestead structure;
- rotation uses the existing placement controls;
- Build confirms relocation without charging materials again;
- Mount/Y dismantles the selected structure;
- dismantling returns half of each recipe material;
- dismantling is refused when storage is non-empty;
- dismantling is refused when the backpack cannot accept the refund;
- legacy fences remain collision participants but are not editable until the legacy renderer is fully retired.

## Safety and compatibility rules

- chest transfers use destination-capacity preflight checks;
- multi-item transfers cannot partially mutate either inventory;
- old over-capacity player inventories remain preserved;
- structure UUIDs remain stable through move, open/close and save/load;
- autosave, manual save, pause save, backgrounding and clean disposal all capture v5 state;
- the install image remains free of ranch saves, settings, logs and local Steam configuration.

## Current architectural boundary

`HomesteadRanchScreen` owns inventory, structure interaction, edit UX and physics orchestration. The old `LivingRanchScreen` is still the validated world renderer/controller. Access to its actor transforms remains isolated inside `LivingRanchTelemetryAdapter` rather than spreading reflection through the domain.

Replacing that adapter with explicit ranch-access interfaces remains a required refactor before the legacy screen is retired. The release does not falsely claim that transition is already complete.

## Presentation status

Structures remain stylized provisional primitives. Production GLB assets, animation state machines and final sound design belong to the later presentation pass. This release focuses on a complete, persistent and controller-usable gameplay loop.

Steam Deck Verified is not claimed. Physical controller, Deck, Proton and Valve compatibility testing are still required.
