## Direct ranch architecture

- `HomesteadRanchScreen` now uses `RanchWorldAccess` directly;
- `LivingRanchTelemetryAdapter` has been deleted from source and packaged runtime;
- camera, active-actor correction, horse correction and camera-obstacle updates cross one typed presentation boundary;
- immutable telemetry records remain the only actor information exposed to the wrapper;
- Windows CI fails if the obsolete adapter or its class returns.

## Selection and move feedback

- the nearest interactive structure receives a translucent non-persistent highlight;
- edit mode keeps the selected origin highlighted while the placement ghost shows the destination;
- HUD feedback shows origin and destination coordinates;
- visual highlighting never mutates structure materials, UUIDs, storage or save state.

## Transactional ranch undo

One session-local operation can be undone:

- an unchanged newly placed structure can be removed with its full recipe returned;
- a relocation can restore the previous transform after the old position passes current placement validation;
- placement undo is rejected after opening, filling or moving the structure;
- relocation undo remains available when the old position is temporarily blocked;
- a filled backpack prevents refund loss and leaves undo available;
- dismantling clears previous undo state;
- undo history is intentionally not written into save v5.

Keyboard uses `U` or `Ctrl+Z`. Controller-only users can choose **Undo Last Ranch Edit** from the Pause screen.

## Camera collision

- third-person camera distance is sampled from the active actor toward the desired camera position;
- terrain and blocking Homestead structures shorten the camera arm;
- open Gates stop affecting the camera together with movement collision;
- the camera pulls inward quickly and returns more slowly to reduce visible snapping;
- collision geometry is pure Java and covered without an OpenGL context;
- legacy trees and rocks are not yet included in this camera pass.

## Ranch effects volume

- `settings.properties` now stores device-local `sfxVolume`;
- old settings files receive the safe 80% default;
- the range is clamped from 0% to 100%;
- changes apply immediately to the shared procedural ranch-audio engine;
- cached waveforms remain immutable and are scaled only for playback;
- unsupported audio devices still degrade safely to silence;
- the setting controls ranch interaction effects, not a future music or ambience bus.

## Compatibility

- save format remains v5;
- no ranch migration is required;
- Gate state, Chest contents, moved structures, inventory, hotbar, horse needs, Pushik and world progress remain compatible;
- undo is session-local and cannot leak into Steam Cloud;
- display and SFX settings remain device-local and excluded from Steam Cloud and the install depot.

## Validation

The release gate covers:

- all existing save v1–v5 migration and recovery tests;
- transactional placement and relocation undo;
- blocked restore and backpack-capacity safety;
- terrain and structure camera collision;
- legacy and round-trip SFX settings;
- deterministic waveform volume scaling;
- direct RanchWorldAccess tests;
- adapter source/JAR absence;
- Java 21 compilation and Windows `jpackage`;
- exact packaged identity and SHA-256 manifest;
- absence of saves, settings, logs and local Steam configuration from the app image.

## Honest presentation boundary

Models, highlight geometry and procedural sounds remain production foundations rather than final authored assets. Camera feel and audio balance still need physical gameplay evaluation. Steam Deck Verified is not claimed; Deck, Proton, controller-family, GPU and Valve review testing remain required.
