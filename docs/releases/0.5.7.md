## Release purpose

0.5.7 responds directly to the successful manual 0.5.6 playtest. It fixes the confirmed mirrored A/D movement, replaces ZIP-only delivery with a normal Windows installer and introduces a first restrained visual pass.

Save format remains **v5**. Existing ranches do not require migration.

## Confirmed control defect fixed

The previous on-foot camera-relative basis used the mirrored planar perpendicular. Default bindings were correct, but `A` and `D` appeared reversed on screen.

0.5.7 introduces the pure `CameraRelativeAxes` contract and uses it in live player movement:

- `A` moves screen-left;
- `D` moves screen-right;
- custom bindings remain unchanged;
- keyboard and controller share the same movement semantics;
- four cardinal camera orientations are covered by regression tests.

## Windows installation

CI produces two independent Windows x64 packages.

### Installer

- per-user EXE installer;
- no administrator rights required;
- destination chooser;
- Start Menu entry;
- desktop shortcut;
- stable upgrade UUID for later versions;
- bundled Java runtime;
- embedded license and third-party notices.

The installer is not code-signed yet. Windows SmartScreen may report an unknown publisher.

### Portable

- self-contained app-image;
- direct `HORSEBOUND.exe` launch;
- no installation required;
- suitable for Steam depot preparation and diagnostics.

## Visual foundation

### Terrain

- grid step reduced from 4 m to 3 m;
- vertex-color meadow variation;
- lowland, highland, shoreline and lake-bed palettes;
- slope-aware shading;
- existing deterministic height and lake collision remain unchanged.

### Procedural models

- player receives shaped body, arms, hands, clothing and boots;
- horse receives refined body masses, face, eyes, blaze, nostrils, articulated leg shapes, mane and tail;
- Pushik receives denser fluffy forms, cheeks, pupils and paws while remaining completely black;
- trees receive branches, layered crowns and bark variation;
- fences receive caps and material variation;
- water receives higher radial resolution and reflective material response.

### Honest limitation

These models are still generated from primitives at runtime. They are a clearer prototype presentation, not production art. The next visual milestone must introduce authored GLB assets, skeletal animations, PBR textures, contact shadows, atmosphere and a dedicated water/sky solution.

## Validation

The release gate requires:

- all existing persistence and gameplay tests;
- camera-relative cardinal-direction regression tests;
- Java 21 compilation;
- Windows portable app-image generation;
- Windows EXE installer generation;
- installer minimum-size sanity check;
- exact packaged version and commit identity;
- required runtime classes in the packaged JAR;
- absence of saves, settings, logs and local Steam configuration from the portable depot;
- independent SHA-256 manifests for portable and installer packages.
