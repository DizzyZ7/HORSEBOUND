## Release purpose

0.5.8 makes the complete player-facing ranch experience available in Russian and English and improves the clarity of the first playable loop. It does not expand the save format or introduce speculative world systems before the existing interaction flow is understandable in both languages.

## Complete bilingual player UX

The localization layer covers:

- main menu and pause menu;
- display, audio, input and key-binding settings;
- save slots, overwrite confirmation and recovery messages;
- HUD, performance overlay and context prompts;
- inventory, hotbar and Chest transfers;
- item, structure and action names;
- build, move, dismantle and undo feedback;
- horse personalities, care values, relationship states and default display names;
- Pushik states and interaction feedback;
- gameplay statuses, warnings and errors intended for the player.

The stored game domain remains language-neutral. Saved item IDs, structure types, horse identities and save DTOs are not translated or rewritten.

## Language behavior

- supported languages: English and Russian;
- first launch follows the operating-system language when it is Russian, otherwise English;
- language is stored in device-local `settings.properties`;
- switching language applies without reinstalling the game;
- a paused ranch refreshes its HUD and status copy after returning from settings;
- missing Russian entries fall back deterministically to English;
- missing keys remain visibly detectable during development instead of silently drawing blank text.

Language is intentionally excluded from ranch save v5 and Steam Cloud planning.

## Unicode UI font

The previous default libGDX bitmap font could not reliably render Cyrillic. 0.5.8 uses a reproducibly generated Unicode BMFont atlas derived from DejaVu Sans.

The build verifies:

- Latin glyphs;
- uppercase and lowercase Cyrillic glyphs;
- punctuation, arrows and interface symbols used by the catalogs;
- packaged `.fnt` and `.png` resources;
- the corresponding font license and third-party notice.

## Mechanics clarity

Outside build or edit mode the ranch HUD displays a derived **Next objective / Следующая цель**. The objective is calculated from current domain state rather than stored as a separate quest flag.

The initial sequence guides the player through:

1. gathering wood;
2. building a feeder;
3. stocking the feeder;
4. building a water trough;
5. filling the trough;
6. building trust with a horse;
7. mounting a horse;
8. continuing ranch development.

Because guidance is derived from inventory, structures, storage and horse state, loading an older save or completing actions in a different order cannot permanently desynchronize the objective.

## Compatibility

Save format remains **v5**. Existing ranches preserve player state, inventory, hotbar, structures, storage, Gate state, horses, Pushik and harvested resources without migration changes.

Input bindings remain in `input.properties`. Display, audio and language remain in `settings.properties`. Both files stay device-local.

## Automated validation

The release gate covers:

- exact English/Russian key parity;
- matching formatting placeholders between languages;
- deterministic English fallback;
- absence of raw user-facing sentences in selected UI surfaces;
- absence of legacy `new BitmapFont()` construction in player-facing screens;
- Unicode font resource and glyph coverage;
- objective progression from actual ranch state;
- settings language persistence and legacy settings compatibility;
- all existing save v1–v5, controller, inventory, building, camera and recovery regressions;
- Java 21 compilation;
- portable Windows app-image and per-user EXE installer;
- required localization classes and resources inside the packaged JAR;
- exact packaged version/commit identity;
- absence of saves, settings, logs and local Steam configuration from the install image.

## Honest test boundary

Automated tests cannot prove that every translated line is ideal in context, that every Russian label fits every resolution, or that no runtime defect exists. Physical testing remains required for text readability, controller prompts, UI scale, font rendering on target GPUs and the complete first-player learning experience.
