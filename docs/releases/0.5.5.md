## Safer ranch workflow

### Visible undo state

- the live ranch HUD shows when the latest build or relocation can be undone;
- the indicator distinguishes the last build from the last move;
- keyboard users can press `U` or `Ctrl+Z`;
- controller-only users can use **Undo Last Ranch Edit** from Pause;
- the Pause entry is visibly disabled when no safe undo exists;
- undo remains session-local and is never written into save v5.

### Two-step dismantle confirmation

Dismantling is now an explicit destructive action:

1. select an editable Homestead structure;
2. press Mount/Y once to arm dismantling;
3. press Mount/Y again within four seconds to confirm.

The confirmation stores the structure UUID and operational revision. It expires or resets when:

- the countdown reaches zero;
- another structure is selected;
- build/edit mode is cancelled;
- the structure is opened, moved, filled, emptied or otherwise mutated;
- undo or another structural operation changes the ranch;
- the ranch session is disposed.

No materials or structures change on the first press. Existing empty-storage and backpack-capacity checks still run before the confirmed dismantle.

## Nature-aware camera collision

The third-person camera now receives typed geometry for the procedural environment:

- unharvested trees;
- rocks;
- closed Homestead structures;
- terrain clearance.

Tree and rock obstacle sizes follow their visible procedural scale. Harvested trees immediately leave both the render list and camera-obstacle list.

Open Gates remain non-blocking for movement and camera collision. Camera pull-in remains faster than recovery to avoid visible snapping when leaving an obstacle.

## Soft near-camera fading

Trees and rocks that sit directly between the active actor and camera fade toward a bounded translucent alpha instead of completely hiding the player.

- fade geometry is pure Java and testable without OpenGL;
- each procedural prop receives isolated material instances, preventing one faded tree from changing every tree;
- alpha is presentation-only and never enters save data;
- off-axis and behind-camera props remain opaque;
- harvested trees cannot remain as invisible occluders.

The first fade pass intentionally covers trees and rocks. Characters, horses and every Homestead model do not yet use a generalized dissolve shader.

## Independent ranch audio buses

`settings.properties` now stores two device-local values:

- `sfxVolume` — construction, Gate, inventory, dismantle and undo feedback;
- `ambienceVolume` — meadow breeze and night cricket ambience.

Both values:

- clamp independently from 0% to 100%;
- apply without restarting the game;
- remain outside ranch saves, Steam Cloud and the install depot;
- preserve legacy settings compatibility.

Defaults are 80% for interaction effects and 45% for ambience.

## Procedural authored ambience profiles

Two low-frequency ambience profiles are introduced:

- **Meadow Breeze** during the day;
- **Night Crickets** during night phases.

The scheduler is deterministic for a ranch seed, uses bounded intervals and pauses while the inventory freezes the world. Waveforms remain procedural and require no external asset files. These are authored production foundations, not final field-recorded or studio-authored ambience assets.

## Compatibility

- save format remains **v5**;
- no ranch migration is required;
- Gate state, Chest contents, moved structures, resource storage, inventory, hotbar, horse needs, relationships, Pushik and world progress remain compatible;
- old `settings.properties` files receive safe ambience defaults;
- existing input profiles remain unchanged.

## Validation

The release gate covers:

- all existing save v1–v5 migration and recovery tests;
- two-step dismantle confirmation, expiry and operational invalidation;
- undo availability through the live session contract;
- tree and rock camera obstacle scaling;
- camera occluder fade geometry;
- harvested-tree camera removal through live world ownership;
- independent SFX and ambience settings round trips;
- legacy settings fallback and invalid-value clamping;
- deterministic ambience cue selection and bounded scheduling;
- procedural waveform bounds and bus scaling;
- Java 21 compilation and Windows `jpackage`;
- required 0.5.5 runtime classes inside the packaged JAR;
- exact packaged version/commit identity and SHA-256 manifest;
- absence of saves, settings, logs and local Steam configuration from the app image.

## Honest hardware boundary

Steam Deck Verified is not claimed. Camera feel, transparency ordering, GPU behavior, Proton compatibility, controller-family semantics and audio balance still require physical gameplay evaluation. Provisional models and procedural sound profiles remain foundations for later production assets.
