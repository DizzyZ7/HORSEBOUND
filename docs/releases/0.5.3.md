## Typed ranch presentation boundary

`LivingRanchScreen` now implements the explicit `RanchWorldAccess` contract.

The Homestead layer receives only:

- the active camera;
- an immutable player or mounted-horse pose;
- immutable horse telemetry snapshots;
- safe position-correction methods for the active actor and individual horses.

Internal `Vector3`, HorseActor and renderer-owned collections are never exposed. `LivingRanchTelemetryAdapter` remains only as a compatibility facade over this interface. It no longer imports reflection, looks up private fields by name or calls `setAccessible`.

A source-level regression test and Windows package gate reject any return of the old reflection bridge.

## Production inventory interaction

Chest transfer controls now support three exact modes:

- Confirm/A transfers one item;
- Build/L1 transfers the selected visual stack;
- Mount/Y transfers every item of the selected type.

All modes are atomic. If the destination cannot accept the complete requested amount, neither inventory is modified. The existing 24-stack backpack, 12-stack Chest and save v5 contents remain unchanged.

Held controller or stick directions repeat after a deliberate delay. Confirm, Back, Build and Mount remain edge-only so holding a button cannot duplicate transfers or destructive actions.

## Gate presentation

Gate collision state still changes immediately when the persistent `open` flag changes. The visible Gate now interpolates between closed and 90 degrees at a deterministic rate.

A Gate restored from a save begins at its saved visual target instead of replaying an opening animation on load. Removed Gates release their animation state.

## Procedural interaction audio

The first ranch interaction cues are generated at runtime rather than shipped as external audio files:

- construction;
- structure relocation;
- dismantling;
- Gate opening and closing;
- successful inventory transfer.

One shared daemon audio engine streams short mono samples through libGDX. Unsupported or missing audio devices degrade to silence without blocking gameplay, saving or shutdown. Waveform generation is deterministic and covered by headless unit tests.

## Persistence and compatibility

Save format remains **v5**. No migration is required from 0.5.2.

Existing data remains compatible:

- Gate open/closed state;
- Chest contents;
- structure transforms;
- feeder and trough storage;
- backpack and hotbar;
- horse needs and relationships;
- player, Pushik and world state.

Steam Auto-Cloud and device-local settings boundaries are unchanged.

## Validation boundary

CI validates Java 21 compilation, all migration and gameplay tests, Windows `jpackage`, controller natives, exact packaged identity, required 0.5.3 runtime classes, reflection removal and depot hygiene.

This is not a Steam Deck Verified claim. Physical controller-family, Deck, Proton, GPU performance and Valve compatibility testing remain required.

Structures still use provisional stylized models. Final GLB assets, authored animation clips and production sound design remain later presentation work.
